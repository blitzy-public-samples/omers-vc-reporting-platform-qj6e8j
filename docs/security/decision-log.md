# Security Remediation Decision Log

This decision log is the single source of truth for the rationale behind the security-remediation engagement on the OMERS Ventures Backend Platform. It mirrors Section 0.10.2 of the Technical Specification and records every non-trivial decision, the alternatives considered, the justification, and the residual risk. The table below has four columns: Decision, Alternatives Considered, Rationale, and Risk.

| Decision | Alternatives Considered | Rationale | Risk |
|----------|-------------------------|-----------|------|
| Keep Pydantic on the v1 line (`1.10.13+`) | Migrate to Pydantic v2 + `pydantic-settings` | Preserves the `BaseSettings` API used throughout; honors the Minimal Change Clause | v1 will eventually be end-of-life; a future v2 migration remains a follow-up |
| Cap FastAPI at `[0.109.1, 0.126.0)` | Upgrade to the latest FastAPI | FastAPI 0.126.0 drops Pydantic v1 support; 0.109.1 already clears CVE-2024-24762 | Misses newest FastAPI features until the v2 migration |
| Version bump, not package replacement | Replace vulnerable packages with alternatives | Every vulnerable package has a maintained patched release; bump is least invasive | None material |
| Bump `cryptography` although it is declared-but-unwired | Leave it pinned at 3.4.8 | It remains in the container image attack surface; hygiene and defense-in-depth | Minor build-surface change, covered by tests |
| CORS: consume an explicit origins allow-list | Set `allow_credentials=False` only | Retains credentialed flows for legitimate origins while removing wildcard exposure | Operators must configure real origins per environment |
| Require secrets from env with a min-length guard | Auto-generate a secret at startup | Mirrors the existing secure pattern; fails closed on misconfiguration | Deployments must set the secret env vars |
| Add the CI scan gate to Azure Pipelines | Add a `.github/workflows` action | The repository uses Azure Pipelines, not GitHub Actions | None |
| Defer `pytest` 6.x→9.x and `loguru` | Upgrade now | Test-only / informational, local-only vectors; three-major `pytest` jump risks breaking tests | Low-severity residual advisory in the dev toolchain |
| Scope observability to security-event logging (reuse logging) | Build full tracing + metrics now | Satisfies the Observability rule while respecting minimal change | Observability remains partial pending the noted follow-up |
| IaC: reference the existing sensitive variable | Wire full Azure Key Vault retrieval now | `variables.tf` already declares the variable; least-invasive removal of the literal | Secret still requires secure provisioning at apply time |
| Advance the base image on the two root containers | Keep `python:3.8-slim` and pin `cryptography < 49` | `python:3.8-slim` is end-of-life; the bump also enables current `cryptography` | Base-image behavioral drift, mitigated by the regression suite |
| No `DELETE` transformations | Remove unwired dependencies / dead code | Out of security-fix scope; deletion could alter behavior | Unwired packages remain (patched rather than removed) |
| `data_transformation`: pin `requests`/`urllib3` to their Python 3.11 patched releases (`2.33.0` / `2.7.0`) and audit this manifest on a Python 3.11 basis in CI | Keep the `2.32.4` / `2.6.3` pins (Python 3.9-compatible) and continue ignoring the advisories in CI | The function app deploys on Python 3.11 (`infrastructure/terraform/main.tf`), where the patched versions (which require Python ≥ 3.10) are installable; masking fixable advisories PYSEC-2026-2275 (`requests`), PYSEC-2026-141/142 (`urllib3`) on a false Python 3.9 justification left the deployed function vulnerable over its outbound FX-rate HTTP path | No backend service masks these `requests`/`urllib3`/`python-dotenv` advisories any longer: the three Python 3.10 services (`authentication_service`, `reporting_financials_service`, `reporting_metrics_service`) take the patched `requests` 2.34.2 and `python-dotenv` 1.2.2 directly (with `urllib3` 2.7.0 transitively), and the two Python 3.9 services (`api_gateway`, `metrics_input_service`) do not depend on `requests`/`urllib3`/`python-dotenv` at all (they use `httpx`). Remaining backend CI ignores are limited to genuinely unfixable-within-envelope advisories — `pytest` (three-major-version jump deferred per §0.6.4), `loguru` (Windows-only, informational), `starlette` (held below 0.51 by the FastAPI < 0.126 / Pydantic-v1 ceiling), and `click` (only on the Python 3.9 services; its fix requires Python ≥ 3.10) |
| `api_gateway`: add `min_length=32` to the `secret_key` setting | Leave the field without a length guard, or remove the vestigial field | Aligns the gateway with the minimum-length enforcement claimed for it (AAP §0.3.2) and mirrors the required-and-validated secret pattern in the authentication/reporting services; adding the guard is the least-invasive of the two options | The field is presently unused at runtime (the gateway validates the signing key via the authentication-service dependency), so there is no behavioral change for a valid configuration |
| Security-test bootstraps provision fail-closed env at package-init top and do **not** mask a broken application import | Wrap the app import in `try/except ImportError` (metrics) or eagerly call `create_app()` at import (financials) | The security regression tests must collect and run in CI while a genuinely broken app import surfaces as a loud collection/runtime error rather than a false-green `app=None`; provisioning env at the very top of `tests/__init__.py` is what lets `config` import during collection (F1/F2/MET-2) | The underlying app-import defects remain until separately fixed; the affected service's non-security suite (`test_financials.py`, `test_metrics.py`) still errors at collection, by design |
| Defer the pre-existing, out-of-scope application-import defects that block full test binding | Fix `app/routers/financials.py:25` (`create_engine(Config.DATABASE_URL)`, invalid class-attribute access under Pydantic v1) and `app/models/models.py` (`from sqlalchemy import UUID`, absent in SQLAlchemy 1.4.x) now | These are pre-existing non-security functional defects outside the security-fix file scope (AAP §0.8.2 "Pre-existing non-security defects"); changing them risks altering application behavior beyond the remediation | Financials `create_app` cannot be imported and the metrics app package cannot be imported until these are fixed (noted follow-up) |
| Financials CORS regression test wires a synthetic app mirroring `main.py` exactly, using the real `config.CORS_ORIGINS` control | Bind the test to the production `create_app()` (as auth/gateway do) | `create_app` is currently un-importable due to the deferred app defect above; the synthetic app still exercises the actual security control (the restricted origin allow-list) and is mutation-sensitive to `allow_credentials`/wildcard changes (F3) | Direct production-factory binding is deferred until the app defect is fixed; documented so the supplement is not mistaken for full production coverage |
| Multi-service test aggregation uses per-service invocation (`pytest src/backend/<svc>/tests`) | Change pytest import mode / restructure the `tests` packages to allow a single aggregate collection | Every service ships a regular `tests` package under namespace parents, so aggregate collection hits a top-level `tests` module-name collision (CS-1); per-service invocation is the documented workflow and avoids it, whereas an import-mode/package-layout migration exceeds the minimal-change security scope | Aggregate (multi-service) collection remains unsupported until a broader test-layout change is undertaken (noted follow-up) |
